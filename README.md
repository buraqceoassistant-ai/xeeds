# Логистика — отгрузки и клиенты (BURAQ logistics)

Сайт и мобильное приложение (PWA) для журнала отгрузок: клиенты, карта точек, дашборд, отчёты,
планы маршрутов A/B/C, тарифы и проверка данных. Работает на компьютере и на телефоне,
ставится на главный экран как обычное приложение и открывается без интернета.

Вход по логину и паролю. Данные хранятся на сайте только в зашифрованном виде.

## Вход и защита данных

- Excel с данными и общие настройки сайта (ссылка на Google Таблицу) зашифрованы случайным
  ключом (AES-256-GCM) и лежат в `data/vault.json`.
- Для каждого пользователя этот ключ зашифрован ключом из его пароля
  (PBKDF2-SHA256, 600 000 итераций). Логины хранятся только как хэши.
- Пароль никуда не отправляется: расшифровка идёт в браузере. Без пароля
  `vault.json` бесполезен, даже если его скачать из публичного репозитория.
- «Запомнить на этом устройстве» сохраняет ключ в браузере, и вход не спрашивается снова.
- «Аккаунт → Выйти» стирает с устройства ключ, локальную копию данных и настройки связи
  с Google Таблицей и Excel. Правки, не записанные в Excel или Таблицу, пропадают:
  перед выходом нажмите «Скачать Excel».

Защита держится на стойкости пароля: используйте сгенерированные пароли (как ниже),
а не короткие и простые.

Открытые данные (`*.xlsx`, `*.csv`) в репозиторий не коммитятся: это запрещено в `.gitignore`,
а сборка сайта падает, если найдёт `.xlsx`.

### Смена пароля на сайте

**Аккаунт → Сменить пароль**: введите текущий пароль, новый (не короче 8 символов) и GitHub-токен.
Сайт проверит текущий пароль, зашифрует ключ новым паролем и сохранит `data/vault.json`
в репозиторий. Через 1–2 минуты GitHub пересоберёт сайт, и новый пароль заработает везде.

Если пользователь на сайте один, при смене пароля меняется и ключ данных: старый пароль
не откроет данные даже из старых версий файла в истории репозитория, а на других
устройствах нужно будет войти заново. Если пользователей несколько, меняется только
пароль того, кто его сменил.

**GitHub-токен** нужен, чтобы сайт мог записать файл в репозиторий. Создаётся один раз:

1. https://github.com/settings/personal-access-tokens/new
2. **Token name**: например, «Смена пароля на сайте». **Expiration**: на ваш выбор.
3. **Repository access → Only select repositories →** `xeeds`.
4. **Permissions → Repository permissions → Contents → Read and write**.
5. **Generate token** и скопируйте токен (`github_pat_…`) в поле на сайте.

Можно отметить «Запомнить токен на этом устройстве», тогда в следующий раз его не придётся
вставлять. Токен стирается с устройства при выходе из аккаунта.

### Пользователи и данные (из командной строки)

Нужен Node.js 18+. Для команд, которым нужен существующий ключ, укажите логин и пароль
любого текущего пользователя:

```bash
# добавить пользователя (пароль сгенерируется и напечатается один раз)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' node tools/vault.mjs add-user manager

# свой пароль вместо сгенерированного
VAULT_LOGIN=buraq VAULT_PASSWORD='…' NEW_PASSWORD='…' node tools/vault.mjs add-user driver1

# вход «только просмотр» (роль viewer)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' NEW_PASSWORD='…' node tools/vault.mjs add-user <логин> viewer

# сменить пароль: добавить того же пользователя с новым паролем
# (роль задаётся заново: без viewer вход получит все права)
VAULT_LOGIN=buraq VAULT_PASSWORD='старый' NEW_PASSWORD='новый' node tools/vault.mjs add-user buraq

# удалить пользователя
node tools/vault.mjs remove-user manager

# секрет редактора для ИИ-импорта (печатается один раз; то же — кнопкой на сайте, см. «ИИ-импорт манифестов»)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' node tools/vault.mjs set-editor

# заменить данные на новый Excel (формат как у исходного файла)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' node tools/vault.mjs set-data Mijozlar_omborlari_ro_yxati.xlsx

# начать заново: новый ключ, новые данные, один пользователь
node tools/vault.mjs init Mijozlar_omborlari_ro_yxati.xlsx buraq
```

После изменения закоммитьте `data/vault.json`. Удаление пользователя закрывает ему вход,
но старые версии `vault.json` в истории git открываются прежним ключом. Чтобы полностью
отозвать доступ, сделайте `init` заново: будет новый ключ и новые пароли. После `init` общие
настройки сайта пустые, поэтому Google Таблицу нужно подключить снова.

### Вход «только просмотр»

У пользователя может быть роль `viewer` (`"role": "viewer"` у его записи в `vault.json`). Такой вход видит всё:
журнал, клиентов, карту, дашборд, планы, 3D, тарифы и проверку, может скачать Excel и обновить данные из таблицы.
Изменить ничего нельзя:
- кнопки правок, «Принять план», «Настройки связи» и смены пароля скрыты;
- поля тарифов и ячейки журнала не редактируются;
- в Google Таблицу и Excel ничего не пишется.

В шапке — метка «Только просмотр», в «Аккаунте» — пояснение. Пароль такого входа меняет руководитель
(командой выше или «Сменить пароль» с логином и текущим паролем этого входа). Ограничение — на уровне сайта:
ключ данных у входа тот же, что у руководителя.

## Данные и синхронизация

Приложение хранит рабочую копию данных в браузере (localStorage). Главный источник данных —
**Google Таблица**, если она подключена. Без неё источник — встроенные данные из `data/vault.json`.

**Google Таблица — одна на весь сайт.**

- Подключается в полосе над журналом: «Google Таблица» → код Apps Script → ссылка `/exec`.
  Ссылка вместе с паролем скрипта сохраняется в общих настройках сайта (зашифрованный
  `vault.json`, коммит «Общие настройки сайта»). Для этого нужен GitHub-токен, тот же, что
  для смены пароля. После пересборки сайта (1–2 минуты) все устройства после входа сами
  работают с этой таблицей. Без токена таблица подключается только на этом устройстве.
- При первом подключении пустая таблица заполняется данными сайта. Если данные отличаются,
  сайт спрашивает: «Взять из таблицы» (сайт покажет таблицу) или «Записать сайт в таблицу»
  (таблица станет как сайт, лишние строки удалятся).
- Правки на сайте сразу уходят в таблицу. Очередь неотправленных правок хранится на устройстве:
  если нет связи или приложение закрыли, правки уйдут при следующем открытии или когда появится
  сеть. Новые строки из таблицы подтягиваются каждые 30 секунд и при возврате в приложение.
- Изменения правил в коде сайта тоже записываются в таблицу. Например, правило
  «первая точка входит в базовую цену» ставит `Sozlamalar!B52 = 1`.
- «Отключить таблицу» отключает её на всех устройствах (нужен GitHub-токен).
- Если сайт пишет «Обновите код скрипта…», значит, код Apps Script в таблице старее сайта и часть
  настроек (например, «точек в базовой цене» у Labo и Kamaz) в таблицу не записывается.
  В окне «Настройки связи» → «Скопировать код» → вставьте в Apps Script → **Развернуть →
  Управление развертываниями** → ✎ → Версия: **новая** → Развернуть. Ссылка останется прежней.

**Excel-файл:** в Chrome и Edge на компьютере файл подключается для записи. На телефоне файл
можно только загрузить, а сохранять через «Скачать Excel».

## ИИ-импорт манифестов

Манифест партии (Excel или PDF) разбирает Claude через скрипт Google Таблицы: ключ API хранится только
в скрипте, на сайт он не попадает. Пользоваться импортом может только руководитель.

### Настройка (один раз)

1. **Ключ Claude API.** [Claude Console](https://platform.claude.com) → [Settings → API keys](https://platform.claude.com/settings/keys) →
   **Create key**. Ключ начинается с `sk-ant-` и показывается один раз — скопируйте его. На счёте в Console должны быть
   деньги: если их нет, сайт так и напишет.
2. **Код скрипта версии 8.** На сайте: полоса над журналом → «Настройки связи» → «Скопировать код» → в Google Таблице
   **Расширения → Apps Script** → заменить весь код → Сохранить → **Развернуть → Управление развертываниями** → ✎ →
   Версия: **новая** → Развернуть. Ссылка остаётся прежней. Если пароль таблицы был вписан в код (`var TOKEN = '…'`),
   впишите его снова или перенесите в свойство `TOKEN` (шаг 3) — тогда при следующих обновлениях его не нужно вписывать.
3. **Свойства скрипта.** В Apps Script **этой таблицы** (Расширения → Apps Script): ⚙ **Настройки проекта → Свойства скрипта → Добавить свойство**,
   затем обязательно **«Сохранить свойства скрипта»** — без этого скрипт свойств не видит:

   | Свойство | Значение |
   | --- | --- |
   | `ANTHROPIC_API_KEY` | ключ из шага 1 |
   | `EDITOR_TOKEN` | секрет редактора: «Настройки связи» → «ИИ-импорт манифестов» → «Показать секрет» → «Скопировать» |
   | `AI_MODEL` | необязательно; по умолчанию `claude-sonnet-5`. Для сканов плохого качества можно `claude-opus-5-5` |
   | `TOKEN` | необязательно; пароль таблицы вместо строки в коде |

4. **Проверка.** «Настройки связи» → «ИИ-импорт манифестов» → **«Проверить ИИ»**: сайт покажет модель и время ответа.
   Если скрипт пишет, что ключа нет, — в ошибке перечислены свойства, которые он видит (только имена).
   Пустой список значит, что свойства не сохранены или добавлены в другой проект Apps Script. Регистр и пробелы в имени
   скрипт прощает, ключ `sk-ant-…` под другим именем тоже находит.

**Секрет редактора** — второй пароль, только для ИИ: скрипт не вызывает Claude без него. Сайт хранит секрет в `vault.json`
в настройках руководителя, зашифрованных отдельным ключом руководителя (у входа «только просмотр» этого ключа нет).
На устройстве, где вход был выполнен раньше, секрет открывается паролем входа («Открыть секрет»). «Новый секрет редактора»
создаёт новый (нужны пароль входа и GitHub-токен) — его нужно снова вписать в `EDITOR_TOKEN`. Если `EDITOR_TOKEN`
не задан, ИИ доступен по обычному паролю таблицы — «Проверить ИИ» об этом предупредит.

**Модель и ответ по схеме.** Скрипт просит у Claude JSON строго по схеме: инструмент со `strict: true` и `tool_choice`
на этот инструмент. Claude Opus 5.5 и Fable 5.1 не принимают принудительный `tool_choice` (ошибка 400) — для них скрипт
передаёт ту же схему через `output_config.format` (structured outputs). Модель меняется свойством `AI_MODEL` без правки кода.

**Лимиты.** Файл — до 10 МБ, PDF — до 30 страниц (запрос к Claude — до 32 МБ, к Apps Script — до 50 МБ, выполнение скрипта —
до 6 минут). Один запрос Apps Script к внешнему API ждёт около минуты, поэтому большие документы разбираются частями.

**«ИИ-журнал».** Каждый вызов — строка в листе «ИИ-журнал» Google Таблицы (скрипт создаёт его сам): время, пользователь,
файл, черновик, действие, модель, часть, токены на входе / из кэша / на выходе, время ответа, итог. Подтверждённые импорты
(дата, маршрут, итоги) сайт берёт оттуда же, чтобы замечать повторный импорт той же партии.

**Маркировки клиента** (как клиент подписан в манифестах: `CBETKO`, `ECLIPSE`…) — поле «Маркировки в манифестах»
в карточке клиента, столбец Y «Markirovkalar» листа «Mijozlar». По ним импорт узнаёт клиента без ИИ.
Пределы плотности груза для предупреждений — «Тарифы» → «Импорт манифестов» (строки 71–72 листа «Sozlamalar»,
по умолчанию 40 и 800 кг/м³).

### Как пользоваться

1. **Загрузка.** Вкладка **«Импорт»** (её видит только руководитель) → перетащить файл или «Загрузить манифест».
   Принимаются `.xlsx` и PDF. Старый `.xls` — пересохраните в Excel как `.xlsx`. Excel сайт читает сам и отправляет ИИ текстом
   (ячейки с адресами), PDF отправляет целиком. Большой документ уходит частями: ~70 строк Excel или 5 страниц PDF.
2. **Черновик.** Ответ ИИ сохраняется черновиком **на этом устройстве** (IndexedDB браузера), переживает перезагрузку.
   До подтверждения в журнал, базу клиентов и Google Таблицу не пишется ничего, кроме строк «ИИ-журнала».
   При выходе из аккаунта черновики удаляются вместе с остальными данными устройства.
3. **Экран проверки.**
   - Слева — документ, справа — строки черновика. Клик по строке подсвечивает её ячейки в Excel или строку на странице PDF.
     На телефоне и планшете документ и строки переключаются кнопками «Строки и клиенты» / «Документ».
   - Все поля правятся: дата партии, консолидатор, маркировка, места, м³, кг. Строки можно добавить и удалить.
   - Итоги, списки и планы A/B/C считает код (тот же `buildPlans`, что во вкладке «Планы»), а не ИИ.
     Из сводки ИИ на экран попадают только слова. Цифры в ней подставляет код.
4. **Проверки кодом.** Цифрам ИИ сайт не доверяет.
   - **Блокирующие** — пока они есть, кнопка «Подтвердить» не работает:
     - число или маркировка не совпадает с ячейкой документа;
     - строка документа пропущена или взята дважды;
     - сумма строк не сходится с итогом TOTAL. Допуск: места — точно, м³ — max(0,01; 0,1 %), кг — max(0,5; 0,1 %).
       Если итог неверен в самом документе, его можно «принять как есть»;
     - у маркировки нет решения по клиенту;
     - нет даты партии.
   - **Предупреждения** — видны у строк, но подтвердить не мешают:
     - число не распознано или не больше нуля;
     - плотность вне пределов из «Тарифов»;
     - в PDF число не найдено в тексте страницы, или страница — скан;
     - в документе нет итога;
     - похоже на повторный импорт: та же дата и те же итоги в журнале, в «ИИ-журнале» или в другом черновике;
     - «Исправлено вами» — вы поменяли число поверх документа.
   - **Списки:**
     - мелкие маркировки — меньше порога «Не платим за доставку» из «Тарифов»;
     - неизвестные маркировки и BL-00 (владелец неизвестен);
     - тяжёлые — плотность выше предела.
5. **Маркировки и клиенты.** Сначала маркировку узнаёт код: по коду `BL-146` / `BL146`, по маркировкам клиента и по бренду.
   Латиница, похожая на кириллицу, тоже сравнивается: `CBETKO` = «СВЕТКО». Остальные маркировки ИИ сопоставляет со справочником.
   ИИ получает только id, имя и маркировки клиентов, без адресов и телефонов. Он предлагает клиента с уверенностью и причиной,
   а решение принимаете вы: «Принять» или «Принять все предложения ИИ», другой клиент из списка или «без клиента».
   Если стоит галочка «Запомнить маркировку у клиента», при подтверждении маркировка допишется в карточку клиента,
   и в следующий раз клиент узнается без ИИ.
6. **Подтверждение.** «Подтвердить и создать партию» создаёт отгрузки тем же путём, что ручной ввод в журнале:
   - одна отгрузка на клиента: строки с его маркировками складываются;
   - машина «Belgilanmagan», статус «Rejada»;
   - в примечании — консолидатор и маркировки.

   Черновик получает статус «Подтверждён» и кнопку «Открыть журнал». В «ИИ-журнал» пишется строка с итогами.
   **«Отклонить черновик»** — партия не создаётся, причину можно указать.
7. **Статистика** над списком черновиков: сколько ждут проверки, подтверждено, отклонено, сколько правок вручную на манифест
   (доля исправленных полей и решений ИИ) — в целом и по моделям. По ней видно, можно ли сменить модель на более дешёвую.

**Реальные манифесты в репозиторий не кладите** — он публичный. Тесты импорта (`tests/import-*.test.mjs`) используют
обезличенный манифест `tests/fixtures/manifest.mjs` и поддельный ответ ИИ `tests/fake-ai.mjs`.

## Клиент по ссылке на карту

В карточке клиента первое поле — «Ссылка на локацию». Вставьте ссылку из Яндекс Карт, Google Карт или 2ГИС (или
координаты «41.31, 69.27»), остальное заполнится само:

- **Координаты** берутся из самой ссылки сразу (`coordsFromLink` в `js/logi-engine.js`). Понимаются метка Google
  (`!3d…!4d…`), `?q=`, `@…`, у Яндекса — `pt`, «Что здесь», поиск по координатам, маршрут, у 2ГИС — объект.
  Перепутанные широта и долгота встают на место по границам Узбекистана.
- **Короткие ссылки** («Поделиться» в телефоне: `maps.app.goo.gl/…`, `yandex.uz/maps/-/…`) раскрывает скрипт
  Google Таблицы (версия 7): он проходит по перенаправлениям, а если координат нет и в полной ссылке, берёт их
  со страницы карты. Без таблицы или со старым скриптом сайт попросит обновить код или вставить полную ссылку.
- **Адрес** (если поле пустое) — геокодер Google Карт через тот же скрипт, на узбекском; без скрипта —
  OpenStreetMap. **Район** (если «Авто») — по адресу, иначе по соседним клиентам. **Зона кольцевой** — по координатам.
- Ссылку можно вставить и в поле широты — сайт поймёт.
- Во вкладке «Проверка» у «Клиенты без координат» кнопка «Найти по ссылкам» заполняет координаты всем, у кого
  ссылка есть, а координат нет.
- Склад отправки — так же: «Тарифы» → «Склад отправки» → «Ссылка на склад». Сейчас склад стоит по ссылке владельца:
  41.383782, 69.233623 (раньше в Excel была примерная точка — сайт заменил её сам, и в Google Таблице тоже;
  координаты склада, которые уже меняли вручную, не трогаются).

При обновлении скрипта до версии 7 Google попросит разрешить скрипту «подключаться к внешним сервисам» —
это нужно, чтобы открывать короткие ссылки.

## Планы маршрутов

Вкладка «Планы A/B/C» раскладывает отгрузки партии по рейсам (`buildPlans` в `js/logi-engine.js`).

- **Машины и автопарк:** 9 Gazel по 19 м³ / 4 000 кг, 1 Changan 9 м³ / 2 000 кг, 1 Labo 3 м³ / 550 кг,
  2 Kamaz 50 м³ / 15 000 кг, у каждой вместимость, тариф и число машин во вкладке «Тарифы» (лист «Sozlamalar»,
  строки 57–58 и 61–69). Рейс никогда не превышает вместимость своей машины и лимит точек плана.
  Рейсы раздаются по машинам: самые длинные — по одному на машину, остальные — вторым рейсом той, что раньше
  вернётся («Gazel-3 · рейс 2», время — после её возвращения), до «Рейсов на машину в день» (2).
  Если рейсов больше — пометка «нет машины» и предупреждение над рейсами.
- **Changan:** без тарифа в планах не используется (поля во «Тарифах» пустые, пока нет цены). Груз без
  объёма и веса не ставится ни на Labo, ни на Changan.
- **Выбор машины:** из машин, в которые груз помещается, берётся самая дешёвая по тарифу.
  Kamaz в планах A и B берёт только груз, который не помещается в Gazel. Машина без тарифа берёт
  только груз, который не помещается ни в одну машину с тарифом, и такие рейсы помечаются «без тарифа».
- **Большой груз:** отгрузка больше самой большой машины делится на несколько рейсов
  (в плане «BL-82 · 1/2», «2/2») с предупреждением над рейсами.
- **Планы:**
  - A — экономичный: самый дешёвый по тарифам без перегруза — Gazel строго до объёма и веса кузова,
    Kamaz только для груза больше Gazel. Много стартовых вариантов (круг вокруг склада, разрезанный
    с разных направлений; объединение рейсов по выгоде; самая плотная раскладка по машинам — сначала к
    ближайшим точкам), потом улучшение, пока сумма падает: расформировать рейс, перенести точку, обменять
    точки. В сумму для сравнения входит и немного за километры — маршруты остаются компактными.
  - B — Gazel и Labo, как можно меньше машин (тот же поиск, что у плана A, до 15 точек в рейсе). Gazel можно загрузить
    с допуском сверх кузова («План B — допуск Gazel», по умолчанию +5 м³ / +500 кг, строки 59–60
    листа «Sozlamalar»); такие рейсы помечены «с допуском». Kamaz — только для груза больше этого.
  - C — только Kamaz. Свёрнут под карточками A и B, открывается кнопкой «Показать».
- **Расходы тремя частями** (`costSplit` в `js/logi-engine.js`). Рейсы и груз не меняются, делится только цена.
  Доля точки считается от цены рейса пропорционально тарифу точки, как «Доля» в журнале. Точка — BL в рейсе,
  её объём — отгрузки целиком (у разделённой большой отгрузки — вся отгрузка). Пункты:
  1. платим — внутри кольца, груз точки от 1 м³;
  2. не платим — груз точки меньше 1 м³;
  3. не платим — точка за кольцом, при любом объёме.

  Где видно:
  - в карточке плана — три пункта под «Итого»;
  - у рейса — «платим … · не платим …»;
  - у точки — метка «не платим» (у мелкого груза — «не платим · < 1 м³»);
  - над рейсами — заметка с числом точек и суммами;
  - в журнале и на дашборде — «платим · не платим» у стоимости рейсов.

  Груз без объёма считается как «платим». Порог (1 м³; 0 — не платим только за кольцом) задаётся полем
  «Не платим за доставку, если груз точки меньше» во «Тарифах», строка 70 листа «Sozlamalar»
  (скрипт таблицы версии 6).

- **Принять план.** Карточка под планами: «Принять план A» (B, C — выбранного плана) записывает в журнал
  машину и номер рейса каждой отгрузке партии. Номер рейса — у машины за день: «Gazel-3 · рейс 2» → машина
  Gazel-3, рейс № 2. Перед записью сайт показывает, что изменится.
  - Большая отгрузка, разделённая на рейсы, становится несколькими строками журнала: первая часть остаётся
    в исходной строке, остальные добавляются. В примечании — «часть 1/2», «часть 2/2». Объём, вес и места
    частей в сумме равны исходным.
  - Отгрузки без координат и статусы не меняются.
  - Новые машины (например, Gazel-7) добавляются в список машин журнала и таблицы.
  - Сразу после записи — «Открыть журнал →» и «Отменить»: отмена возвращает прежние машины и рейсы
    и убирает добавленные части (их узнаёт по содержимому, даже после синхронизации с таблицей).
  - Отметка «✓ План записан» держится, пока журнал партии совпадает с планом.

  Сумма рейсов в журнале совпадает с планом: точки рейса считаются в порядке объезда, как в плане
  (ближайшая к складу, потом ближайшая к ней), поэтому в базовую цену входит та же первая точка.

Листы «Reja A/B/C» в Excel считаются своими формулами и этих правил не знают. Для решений используйте вкладку «Планы» на сайте.

## Отчёты

Вкладка «Отчёты» (`reportBatch`, `reportView` в `index.html`), три отчёта:

- **Партия на день.** Рейсы по машинам и точки в порядке объезда: клиент, адрес, получатель и телефон,
  объём, вес, места, прибытие, зона, доля цены. Итоги: отгрузки, объём, рейсы, пробег, стоимость
  и расходы тремя частями (платим / не платим < 1 м³ / не платим за кольцом). Внизу — отгрузки без рейса.
- **Расходы за период.** Итоги и таблица по партиям (стоимость, платим, не платим, сум за м³),
  стоимость по машинам и по районам.
- **Автопарк и экономия.** По видам машин: машин в парке, рейсы, самый загруженный день, сколько машин
  нужно в этот день и сколько рейсов можно в день (машин × «Рейсов на машину в день»), средняя загрузка,
  рейсы загруженные меньше чем наполовину. Сравнение планов A, B, C и журнала по партиям и выводы.

Откуда берутся рейсы и стоимость:
- если у партии в журнале есть рейсы (машина и номер рейса, например после «Принять план») — из журнала;
- иначе — из плана A, с пометкой «по плану A».

Время рейсов по журналу:
- первый рейс машины выезжает в начале дня;
- следующий рейс этой машины — после возвращения предыдущего.

Особые случаи:
- Рейсы без тарифа (сейчас Kamaz) в сумму не входят и помечаются «+».
- Партии, где у отгрузок пустые CBM и KG, входят в стоимость, но не входят в загрузку и цену за м³. Отчёт об этом предупреждает.
- «Самый дешёвый» план не указывается, если у другого плана есть рейсы без тарифа и уже известная сумма меньше.

Период для расходов и автопарка:
- месяц (по умолчанию — месяц последней партии);
- всё время;
- свой период: с … по ….

Выгрузка:
- **Скачать Excel** — выбранный отчёт отдельным файлом: лист «Итоги» и таблицы отчёта. Имена файлов латиницей:
  `BURAQ_partiya_2026-08-27.xlsx`, `BURAQ_xarajatlar_2026-08.xlsx`, `BURAQ_avtopark_2026-08.xlsx`.
- **Печать / PDF** — печатается только отчёт, на A4:
  - сверху логотип BURAQ, название отчёта и время формирования;
  - меню и кнопки скрыты;
  - длинные таблицы переходят на следующую страницу по строкам, заголовок таблицы повторяется;
  - чтобы получить PDF, в окне печати выберите «Сохранить как PDF».

Отчёты видит и вход «только просмотр».

## Визуализация загрузки (3D)

Вкладка «Визуализация» показывает рейсы плана в 3D: все машины партии рядом или один рейс
(кнопка «Загрузка 3D» у рейса во вкладке «Планы» открывает его сразу).

- **Груз:** размеров мест в данных нет, поэтому груз каждой точки раскладывается кубиками по объёму
  (CBM). Порядок — как при разгрузке: последнюю точку грузят первой к кабине, точка 1 у дверей.
  Груз сверх кузова (допуск плана B) показан за дверями полупрозрачным.
- **Кузов:** Labo — бортовой, по данным производителя (UzAuto): 1,94 × 1,33 м, борт 0,29 м, колёсная база
  1,84 м; высота груза — из объёма Labo во «Тарифах» (3 м³ ≈ 1,16 м). Changan, Gazel и Kamaz — фургоны
  с типичными шириной и высотой, длина — из объёма во «Тарифах».
- **Машины:** у каждой марки своя кабина. Gazel — с коротким капотом, Changan — полукапотная, Labo и Kamaz —
  кабина над двигателем. У всех колёса с дисками, фары, зеркала и бампер. Раскраска — в фирменных цветах:
  белая кабина, синий низ, красная полоса и логотип BURAQ на дверях; у Kamaz кабина синяя с белым логотипом.
  Стенки фургона — как тонированное стекло, груз виден. Мягкие тени и отражения.
- **Разгрузка по точкам:** ползунок и ▶ убирают груз выгруженных точек (коробки выезжают через двери);
  нажатие на груз выделяет точку. При открытии рейса груз укладывается по порядку — от кабины к дверям.
- **Плавность:** камера вращается с инерцией и плавно перелетает между видами и рейсами. Шейдеры собираются
  в фоне, а сцена проявляется, когда готова. При уходе с вкладки сцена сохраняется, поэтому при возврате
  открывается сразу. Если в системе включено «Уменьшить движение», всё работает без анимаций.
- **Скорость:**
  - неподвижные детали всех машин слиты в одну сетку на материал: десятки вызовов отрисовки вместо сотен;
  - тени считаются один раз на сцену, а не каждый кадр;
  - груз, земля, резина и рама — с простым быстрым материалом;
  - в обзоре коробки без скруглений;
  - чёткость не выше 1,5 и сама снижается, если устройство не успевает;
  - на ноутбуке используется мощная видеокарта.
- Раскладка — `LogiViz.layout` в `js/logi-viz.js`, сцену рисует three.js: своя сборка
  `js/vendor/three/three-viz.min.js` (как собрать — в `tools/three-viz-entry.js`), работает и без интернета.

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.

При каждой сборке service worker получает новую версию кэша, поэтому телефоны

## Локальный запуск

```bash
python3 -m http.server 8000
# http://localhost:8000
```

На `localhost` service worker отключён, чтобы правки были видны сразу.
Включить для проверки: `http://localhost:8000/?sw=1`.
