# Учебная платформа BURAQ (learn/)

Обучение сотрудников: курс по стандартам компании, тесты и устный экзамен у методиста, план адаптации 30/60/90,
уровни, рейтинг, журналы и термины, кейсы, ошибки и наставники, сверхзадачи, опросы, учёт турникета.
Роли: **методист** (admin) и **сотрудник**; наставник — сотрудник с отметкой «наставник».

Адрес на сайте: `https://<владелец>.github.io/<репозиторий>/learn/`.

| Путь | Что это |

| `learn/lor-ds.js` | Компоненты дизайн-системы (`window.LOR`): кнопки, шапка, защищённый просмотр, плеер |

| `learn/strings.js` | Надписи на четырёх языках: uz (основной), ru, en, zh |
| `learn/app.js` | Приложение |

(`tools/i18n/uz.txt`) к платформе не относится.

## Сейчас: демо

Пока страница не связана с сервером (это шаг 3, план ниже), `learn/` работает как прототип: данные — только в этом
браузере (localStorage), на экране входа — демо-входы (`metodist / admin123`, сотрудники — пароль `1234`),
«Demo ma’lumotlarni tiklash» возвращает примеры.

**Тексты стандартов «4-bob» в репозиторий не попадают:** репозиторий открытый. В демо у уроков 4.1–4.20 только номера
и названия, текст — заглушка, тест — три демо-вопроса. Настоящие тексты и тесты методист загрузит на сервер, а
сотрудники получат их только после входа.

ИИ-помощники (наставник, кейсы, опросы, редактор курса) вне claude.ai выключены — сервер для них будет на шаге 5.

## Сервер

Отдельный проект Google Apps Script — **не** скрипт таблицы отгрузок. Бесплатно, своего сервера не нужно.

- **Данные** — один файл `state.json` в папке «BURAQ o‘quv platformasi — ma’lumotlar» на Google Диске владельца
  скрипта. Каждую ночь в 03:00 (Ташкент) — копия в `backups/state-ГГГГ-ММ-ДД.json`, копии хранятся 30 дней.
- **Вход** — логин и пароль проверяет сервер. Пароли хранятся только как PBKDF2-SHA256 с солью (10 000 повторов)
  в свойствах скрипта, в `state.json` их нет. После 5 неверных паролей подряд логин закрыт на 15 минут. Вход на
  устройстве живёт 30 дней с последнего запроса, у одного человека — до 10 устройств.
- **Что видит сотрудник:** правильных ответов тестов нет ни у кого, кроме методиста. Закрытые разделы — только
  названия уроков, до конца испытательного срока. Чужие анкеты, опросы, заявки и уведомления скрыты. Про коллег
  он видит только то, из чего считается рейтинг: должность, уровень, статус и балл уроков, минуты учёбы.
  Журналы и термины — по правам доступа, которые задал методист, кейсы — только опубликованные.
- **Что сотрудник может менять:** только своё — анкету, план адаптации, «читаю / вопрос / готов к тесту» в уроке,
  свои заявки, идеи, опросы, отметки «ознакомлен». Уровень, статус, итог урока, сверхзадачи, курс меняет методист.
  Балл теста считает сервер по ответам (действие `quiz`), один раз после «Готов к тесту». Наставник ещё записывает
  ошибки подопечным. Каждая отклонённая правка возвращается с причиной.
- **Методист** меняет всё. Пароль в карточке сотрудника сервер переносит в учётную запись и из данных убирает;
  удалённый сотрудник сразу теряет вход.

### Настройка (один раз, ~10 минут)

1. Войдите в Google под аккаунтом **buraqceoassistant@gmail.com** — данные платформы будут на его Диске
   (решение владельца, 10.10.2026).
2. [script.google.com](https://script.google.com) → **Новый проект** → назовите «BURAQ o‘quv platformasi».
3. Откройте на GitHub файл `tools/lms-gs/Code.gs` → **Raw** → скопируйте всё → вставьте вместо кода в редакторе →
   **Сохранить**.
4. Вверху выберите функцию **`setup`** → **▶ Выполнить** → «Проверить разрешения» → свой аккаунт → «Дополнительные
   настройки» → «Перейти к проекту» → **Разрешить** (Диск — для данных, триггеры — для ночной копии).
5. Внизу, в «Журнале выполнения» — **логин и пароль методиста**. Запишите: пароль больше нигде не показывается.
6. **Развернуть → Новое развертывание** → ⚙ Тип: **Веб-приложение** → Выполнять как: **Я**, Доступ: **Все** →
   **Развернуть** → скопируйте ссылку `…/exec`. Её вставим в страницу на шаге 3.
   Проверка: ссылка в браузере отвечает `{"ok":true,"app":"buraq-lms","v":1,"ready":true}`.

Забыли пароль методиста — в редакторе функция **`newAdmin`** → ▶ Выполнить: новый вход методиста (`metodist2`, …)
в журнале выполнения.
Обновление кода сервера: вставить новый `Code.gs` → Сохранить → **Развернуть → Управление развертываниями** → ✎ →
Версия: **новая** → Развернуть. Ссылка не меняется.

### Запросы

POST на `…/exec`, тело — JSON (`Content-Type: text/plain`, чтобы браузер не делал предварительный запрос),
ответ — `{ ok: true, … }` или `{ ok: false, code, error }`.

| action | Кто | Что делает |
| --- | --- | --- |
| `ping` | все | версия сервера, настроен ли |
| `login` `{login, password}` | все | `{token, me, rev}`; коды ошибок `login`, `locked` |
| `logout` | вошедший | закрывает вход на этом устройстве |
| `load` | вошедший | `{rev, me, state}` — состояние, которое ему положено видеть |
| `since` `{rev}` | вошедший | `{same: true}`, если ничего не менялось, иначе как `load` |
| `patch` `{ops}` | вошедший | правки (`learn/lms-sync.js`), `{rev, applied, rejected: [{i, reason}]}` |
| `quiz` `{lessonId, answers}` | вошедший | балл теста и правильные ответы — после сдачи |
| `password` `{old, password}` | вошедший | смена своего пароля (от 8 символов), другие устройства выходят |
| `resetPassword` `{userId}` | методист | новый пароль сотруднику — показывается один раз |

Другие коды ошибок: `auth` — нужен вход, `forbidden` — нет прав, `busy` — сервер занят записью (повторить),
`setup` — не запущен `setup`, `bad` — неверный запрос.

## Шаг 3 — план: связать страницу с сервером

Цель: `learn/` по умолчанию работает с сервером, демо — по `learn/?demo=1`.

1. **Адрес сервера** — `learn/config.js`: `window.LMS_SERVER = '…/exec'`. Адрес не секрет: без логина сервер ничего не
   отдаёт. Пустой адрес — только демо.
2. **Вход.** Форма входа отправляет `login`; токен — в localStorage. Блок «Demo hisoblar» и «Demo ma’lumotlarni tiklash» —
   только в `?demo=1`. «Chiqish» — `logout`. Ошибки по кодам (`login`, `locked`, `busy`, `setup`, нет сети) —
   надписи на 4 языках в `strings.js`.
3. **Данные.** `useDB` берёт состояние с сервера (`load`) и держит копию на устройстве для работы без сети.
   `update(fn)` меняет состояние, как сейчас, затем `LmsSync.diff(было, стало)` → очередь правок на устройстве →
   `patch` пачками раз в секунду. Отклонённая правка — сообщение и `load`. Раз в 30 секунд и при возврате
   на вкладку — `since`. Язык и вход (`lang`, `session`) остаются на устройстве.
4. **Правки страницы, без которых сервер будет отклонять правки** (нашлись при разборе всех 96 мест `update(…)`):
   - `nextId` берёт `d.seq + 1` — на двух устройствах номера совпадут. Нужен уникальный id: время и случайная часть.
   - Тест урока (`QuizView`) считает балл на странице, а сотруднику правильные ответы больше не приходят: отправлять
     ответы в `quiz` и показывать балл и разбор из ответа сервера.
   - `audit` (нарушения защиты урока) — записи без id и обрезка `slice(0, 200)` на странице: дать записи id,
     обрезку перенести на сервер.
   - Месячный отчёт (`issueMonthly`) запускается у каждого, кто открыл страницу, — оставить только у методиста.
   - `migrate()` с демо-номерами (v8…v22, ID 10288 и т. п.) — только для `?demo=1`.
   - Пустая платформа у методиста: уровни, программы, план адаптации, график работы — кнопка «Заполнить из шаблона»
     (`seedLevels`, `seedTracks`, `seedPlan`, `seedSchedule`).
   - Курс: «Загрузить курс из файла прототипа» — методист выбирает свой `.html` прототипа, страница берёт из него
     раздел 4-bob и отправляет на сервер. Тексты по-прежнему не попадают в репозиторий.
     Вводный раздел прототипа «Kompaniya bilan tanishuv» — пример, а не правила компании: на сервер он не переносится,
     настоящий вводный раздел пишет методист. В демо пример остаётся.
   - Новый сотрудник: пароль показывается методисту один раз (сервер его не хранит и не возвращает),
     «Сбросить пароль» — `resetPassword`.
5. **Проверка правил на всех сценариях.** Тест прогоняет действия сотрудника и наставника из демо через сервер на заглушке:
   ни одна обычная правка не должна отклоняться. Если отклоняется — уточнить правило в `checkEmployee_`.
6. **Проверка в браузере** (Playwright): методист создаёт сотрудника → сотрудник входит на другом «устройстве» →
   читает урок, сдаёт тест → методист видит заявку и ставит итог → сотрудник видит итог. Плюс правка без сети, которая
   уходит после её возвращения.
7. **Код сервера со страницы:** у методиста «Сервер» → «Скопировать код» (как у сайта отгрузок) и предупреждение,
   если код сервера старее страницы.

## Дальше

- **Шаг 4 — файлы на Диске:** шаблоны журналов, файлы сверхзадач (и анкета — после решения по паспортам) — в папке
  на Диске через сервер, открывает только тот, кому разрешено. Сейчас файлы хранятся внутри данных.
- **Шаг 5 — ИИ через сервер:** ключ Claude API в свойствах скрипта, журнал вызовов, лимит запросов на сотрудника в день.
- **Шаг 6 — запуск:** реальные сотрудники и курс, видео (сейчас — заглушка плеера), инструкция для методиста.

## Известные ограничения

- XP за опросы и ИИ-тренировки считает страница — при желании их можно накрутить через инструменты разработчика.
  Итог урока решает устный экзамен у методиста, его сотрудник не поставит.
- Все данные — один файл: каждая запись переписывает его целиком. Для десятков и сотен сотрудников этого хватает.
  Если станет медленно, файл можно разделить (курс, люди, журналы).
- Apps Script отвечает за 1–2 секунды; вход — чуть дольше (хэш пароля).
